# Vercel environment audit

This document was produced by inspecting actual source usage — every row below traces to a real `process.env[...]` read (or an explicit absence of one) found by searching the repository, not to assumption or to what `.env.example` merely lists. No real secret value appears anywhere in this file.

**Updated for Gate 11.** The prior version of this document (product-repair audit) found `DATABASE_URL` completely unconsumed and flagged SQLite persistence as incompatible with Vercel's serverless filesystem. Gate 11 closes that gap: `DATABASE_URL` is now genuinely consumed when `MARKED_STORAGE_DRIVER=postgres` is set. See `evidence/production-persistence/` for the full implementation, schema, and proof status.

## Read this first: Postgres mode is implemented and proven against a real hosted database

Gate 11 added `PostgresFulfillmentJobStore` (`packages/db/src/postgres-fulfillment-job-store.ts`) and an explicit driver-selection factory (`apps/web/src/lib/job-store.ts`). With `MARKED_STORAGE_DRIVER=postgres` and a real `DATABASE_URL`, the app's persistence is durable Postgres, not a local file — the Vercel-incompatibility the prior audit flagged is solved, both architecturally and now by real exercise. A real hosted Neon Postgres database was migrated (`pnpm db:migrate`) and the full mandatory test suite — the shared contract battery, concurrent-worker races, forced-failure transaction rollback, restart/reconnect, and JSONB serialization round-trip — was run against it for real: all passing. See `evidence/production-persistence/hosted-production-proof.md` for the full account and `evidence/production-persistence/gate11-result.md` for the verdict.

Setting `MARKED_STORAGE_DRIVER=postgres` on a real deployment (Vercel or otherwise) still requires supplying that deployment's own real `DATABASE_URL` and running `pnpm db:migrate` against it first — this document proves the code path works, it does not configure any specific deployment on your behalf. Leaving `MARKED_STORAGE_DRIVER` unset (the default) keeps the app on SQLite, which is honest but does not survive Vercel's serverless filesystem for ARM/APPROVE/DISARM (same caveat as before Gate 11). Read-only pages — the landing page, `/demo`, `/proof/gate6`, `/evidence`'s static content, `/docs`, and `/app/new`'s resolution/preview up to but not including arming — are unaffected either way.

## What this means for `.env.example` and `packages/config`

`DATABASE_URL` has been promoted out of "NOT REQUIRED" in this update — it is now genuinely load-bearing, conditionally on `MARKED_STORAGE_DRIVER=postgres`. The KeeperHub and legacy safety-flag variables remain inert for the reasons above; `.env.example` labels them accordingly. `@marked/config`'s `EnvSchema`/`parseEnv` (the Zod schema in `packages/config`) still is not the mechanism that reads `DATABASE_URL` or `MARKED_STORAGE_DRIVER` — `job-store.ts` reads `process.env` directly, matching the pattern every other consumed variable in this document already uses (`governance.ts`, `agent/provider.ts`, `session.ts`). Wiring `@marked/config` into the app's actual startup path remains a real, separate follow-up, not something this gate performs.

## How to actually run Postgres on Vercel once a database exists

1. Set `DATABASE_URL` (server-only environment variable, in the Vercel project's environment variable settings — never in a committed file).
2. Run `pnpm db:migrate` with that same `DATABASE_URL` set locally (or via a one-off Vercel deployment step) — this creates `fulfillment_jobs`, `job_events`, `execution_claims`, and `schema_migrations`. It is safe to re-run.
3. Set `MARKED_STORAGE_DRIVER=postgres`.
4. Redeploy. `getAppStore()` will now construct `PostgresFulfillmentJobStore` instead of the local SQLite store.

Do not set `MARKED_STORAGE_DRIVER=postgres` before step 2 — the app will fail closed with `PersistenceConfigurationError` on first use if the tables don't exist yet (surfaced as a real Postgres "relation does not exist" error wrapped by the store), which is the correct, honest behavior — not a bug to work around.
