Technical evidence

Evidence, not claims.

Every load-bearing claim in Marked should point to something reproducible.

—By gate

What was proven, gate by gate.

Gate 1A
PROVEN

Cactus resolution

Real mainnet proposals (Compound #220, Uniswap #20) resolved to organization/chain/Governor/onchain proposal ID through live Cactus infrastructure, independently cross-checked onchain.

evidence/cactus/compound-220/evidence/cactus/uniswap-20/pnpm prove:cactus

Limitation: Resolved via the documented SSR fallback, not the authenticated official GraphQL API (no API key available in this environment).

Gate 1B
PROVEN

KeeperHub execution surface

Direct execute-contract-call on Sepolia, with explicit typed authorization, full local pre-network validation, and an independently-verified onchain write.

evidence/keeperhub/probe-001-erc20-approve/

Limitation: Only Option B (direct contract-call) is proven — Option A (KeeperHub Workflows) is untested.

Mode C
PROVEN

Claim boundary (Cactus × KeeperHub)

Cactus integration (live mainnet reads) and KeeperHub fulfillment (controlled Sepolia writes) are proven separately and never narrated as one continuous closed loop.

evidence/closed-loop/classification.md

Limitation: No Cactus-indexed proposal has ever been executed through KeeperHub end to end.

Gate 2
PROVEN

Governor authorization engine

A deterministic, versioned actionAuthorizationHash is reconstructed directly from a Governor Bravo contract's own storage — never from Cactus, prose, or an LLM.

evidence/governor/compound-220/pnpm prove:governor

Limitation: Governor Bravo only — no other Governor family is implemented.

Gate 3
PROVEN

Economic postcondition (ERC20TransferAdapter)

Verifies an exact recipient balance delta plus an execution-bound Transfer log. Proven to refuse on every tested mismatch, including fee-on-transfer and rebasing tokens.

evidence/postconditions/historical-fixture/pnpm prove:erc20-postcondition

Limitation: transfer(address,uint256) only — no transferFrom, fee-on-transfer, or rebasing support.

Gate 4
PROVEN

Fulfillment commitment & state machine

A versioned fulfillmentCommitmentHash freezes the reviewed authorization. Every illegal state-machine shortcut, including any route to MARKED ✓, is structurally impossible.

evidence/fulfillment-commitment/pnpm prove:fulfillment-commitment

Limitation: No production (Postgres/Drizzle) persistence backend — see Gate 7.

Gate 5
PROVEN

KeeperHub Governor lifecycle fulfillment

A controlled Sepolia Governor Bravo proposal genuinely passed propose → vote → queue, and KeeperHub called the Governor's own execute(proposalId).

evidence/lifecycle-fulfillment/

Limitation: One controlled proposal, one controlled Governor — not a real DAO.

Gate 6
PROVEN

Independent economic verification & Marked Receipt

The first legal MARKED ✓ — every fact independently re-derived from live chain state, reconciled across six required legs with no single-signal shortcut possible.

evidence/marked-receipt/pnpm verify:gate6

Limitation: Covers exactly one controlled Sepolia fixture.

Gate 7
PROVEN

Recovery hardening & authentication

Real SQLite-backed persistence surviving an actual process restart; ambiguous-execution resubmission is structurally excluded; duplicate-worker protection is a real DB compare-and-set; mutating routes require an authenticated actor.

evidence/recovery-hardening/

Limitation: Single-file/single-process database, not distributed infrastructure. Demo session-token auth, not wallet/SIWE.

Gate 10
PROVEN

Agent hardening — the deterministic boundary

A strict, unknown-field-rejecting schema plus a deterministic validator mean an LLM's output can never itself become an armable plan — recipient/amount/target/calldata/governor/proposalId don't exist as fields the agent can supply at all. Prompt injection in governance text is treated as inert data by construction.

evidence/agent-hardening/pnpm --filter @marked/core test -- agent-plan

Limitation: No live model provider is configured in this deployment (no API key) — the agent's read/prepare features gracefully report 'unavailable'; the deterministic validator itself is fully proven regardless via hand-authored fixtures standing in for both benign and adversarial model output.
