# Gate 10 → Gate 10L — live model status

**Update (Gate 10L):** a real, currently-free hosted model (`nex-agi/nex-n2.5-pro:free`, via OpenRouter) *was*
exercised live through this exact provider boundary during development — see `evidence/agent-hardening/live-model/`
for the real, captured proof (four separate live proofs, zero blockchain writes, real network calls to
OpenRouter/Cactus/Ethereum RPC). This file's original Gate 10 content is kept below because it remains true
of the **shipped, committed repository**: no API key is committed anywhere — `apps/web/.env.local` is
gitignored, the OpenRouter key used for the live-model proof exists only in that local, untracked file, and
was never written to any file under version control. A fresh clone of this repository ships with no key, so
it defaults to "Agent unavailable" exactly as described below, until an operator supplies their own key. Both
facts are true simultaneously: "a real model was exercised and evidenced during this gate" and "the shipped
repository defaults closed with no key committed."

## The honest default state (a fresh clone, unchanged by Gate 10L)

`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, and `LLM_API_KEY` are all unset in a fresh clone of this
repository. `getAgentProvider()` (`apps/web/src/lib/agent/provider.ts`) returns `null` in that state, and
every agent-facing surface (`AgentPanel` on `/app/new`, `/app/fulfillments/[id]`, and `/proof/gate6`) renders
the honest "Agent unavailable — the model provider is not configured on this server" state rather than
fabricating a response. This was verified live: `apps/web/src/lib/agent/actions.test.ts`'s "unavailable"
describe block exercises the actual current `getAgentProvider()` result (not a mock) for all four agent
actions, and remains passing after Gate 10L.

## What was built and proven

- `AnthropicAgentProvider` and `OpenRouterAgentProvider` — both real, working API clients (`fetch` to their
  respective real endpoints, real request/response shapes, real JSON-parsing and code-fence stripping for
  structured output). `provider.test.ts` proves `OpenRouterAgentProvider` parses OpenRouter's real response
  shape and fails closed (never silently substitutes anything) on a token-budget cutoff or an in-body error.
- The deterministic validator (`validateAgentPlan`) and its 32-test suite need no model call at all — they
  are tested directly against hand-authored candidate objects representing both benign and adversarial "model
  output." See `adversarial-results.md`.
- `apps/web/src/lib/agent/actions.test.ts`'s "available" describe block proves the *orchestration* layer
  (context building → provider call → validation → response shape) end-to-end with a mocked `fetch`.
- **Gate 10L's addition**: `pnpm prove:agent-live-model` performed the same orchestration for real, against
  the real OpenRouter API, with real Compound #220 Cactus/Governor resolution and the real Gate 5/6 evidence
  as context. See `live-model/README.md`.

## What is still NOT claimed

No live model response is generated by default when someone else clones this repository — they must supply
their own `OPENROUTER_API_KEY` (or `ANTHROPIC_API_KEY`) first; none is provided. The `/demo` replay's two
"illustrative" agent-narration steps remain hand-written UI copy, explicitly labeled as such, not a captured
model transcript — Gate 10L's real live calls targeted `/app/new`, the Gate 5/6 fixture (read-only, no
broadcast), and the canonical receipt directly, via the standalone proof script, not the `/demo` stepper.

## To light this up live yourself

```bash
export MARKED_AGENT_PROVIDER=openrouter
export OPENROUTER_API_KEY=sk-or-v1-...
pnpm dev
```

No code change is required — `getAgentProvider()` picks up the key automatically. Run
`pnpm prove:agent-live-model` for a fresh, real, four-proof transcript of your own.
