# Gate 12 §4 — trust-boundary map

| Boundary | Source | Trust level | Validation/normalization | Authority | Failure mode | Timeout | Retry | Logging | Secret risk |
|---|---|---|---|---|---|---|---|---|---|
| **USER → URL input** | `/app/new?url=` form (GET) | Untrusted | `packages/cactus/src/url.ts`: `https:`-only, exact-match host allowlist (4 hosts), strict path regex; URL rebuilt from only `hostname`+`pathname` (strips userinfo/query/fragment) | None — only decides which Cactus proposal to look up; the actual authorization is independently re-derived on-chain, never from this URL | Typed `CactusResolutionError`, never falls back to raw user coordinates (verified: no code path builds a `GovernanceCoordinate` from the raw string) | Not explicit on the fetch itself; bounded by the outer request | None (single attempt) | No secret ever in this value |
| **USER → questions (agent Q&A)** | 4 Server Actions in `agent/actions.ts` | Untrusted, unauthenticated | Gate 12 fix: length-capped (2000 chars), rate-limited (5/60s/caller-key) — see F-04 | None — read-only, never mutates a job (see `agent-audit.md`) | Returns `{ok:false, reason}`, never throws to the caller | Upstream provider's own timeout | No app-level retry | Provider errors surfaced via `AgentProviderError`, never raw stack/key | Provider API key never touches this path's inputs/outputs |
| **USER → auth/session values** | `marked_demo_session`/`marked_demo_actor` cookies, or `x-demo-token`/`x-actor-id` headers | Untrusted input, but see F-03: the cookie path's token check is a server self-comparison, not a real secret gate | `requireAuthenticatedActor` (constant-time compare after this gate's fix); `actorId` only checked non-empty, never allowlisted | Gates ARM/APPROVE/DISARM; does NOT gate read of `GET /api/fulfillment/state` (intentionally public) | `UnauthenticatedError`, fails closed before any store write | N/A | N/A | Real token never logged; `actor` free text IS recorded permanently in the event log | Real token never sent to browser in any form (verified: `SESSION_COOKIE` value is the literal `"1"`) |
| **CACTUS → HTML/SSR data** | `packages/cactus/src/ssr-fallback.ts` (fallback path only) | Semi-trusted (allowlisted host, see F-11 for the one gap — redirect final destination not re-validated) | Regex/structural parse of `__NEXT_DATA__`; malformed shape throws typed error | Discovery only — never authorization | Typed `CactusResolutionError` | Not set explicitly on this fetch | None | No response body logged | None |
| **CACTUS → official GraphQL API** | `packages/cactus/src/graphql-client.ts`, hardcoded endpoint `https://api.tally.xyz/query` | Trusted transport (fixed, non-user-controlled URL); response still structurally validated | Zod-shaped parse of the GraphQL response | Discovery only | Typed error on auth-rejected/malformed response, then falls through to SSR fallback | Not set explicitly | None | No key/response logged | `CACTUS_API_KEY` only ever in the `Authorization` header |
| **RPC → onchain reads** | `packages/governor/src`, `apps/web/src/lib/governance.ts` (viem) | Trusted-but-verify: independently re-read every time, never cached across the authorization-decision boundary | Decoded via known ABI; a decode/shape mismatch throws | **This is the actual authority source** — the one boundary every other input must reduce to | Errors propagate as thrown exceptions; ARM's caller (`fulfillment-actions.ts`) does not catch-and-fallback, so an RPC failure blocks ARM rather than silently proceeding | viem/fetch defaults (no explicit override found) | viem defaults; not independently configured by this app | RPC URL not logged; may embed a provider API key — see `env-audit.md` | RPC URL embedding a key is a real secret if set — never logged anywhere found |
| **LLM → candidate plan / explanations** | `apps/web/src/lib/agent/provider.ts` | Explicitly hostile per product design (Gate 10) — never authoritative | `validateAgentPlan` (deterministic, `packages/core`) re-derives/checks every authority-shaped field against the real on-chain-resolved context; the model's own output is never trusted for value | None — the model may only compose from data already independently resolved | `AgentProviderError` on malformed/failed response; agent unavailability never mutates job state (proven by `agent-actions.test.ts`'s before/after snapshot tests) | Provider default (no explicit timeout found — a gap, see `agent-audit.md`) | None | API key only in `Authorization`/`x-api-key` header (test-proven never elsewhere) | Key never reaches client bundle (traced: only booleans/bound Server Action refs cross into `AgentPanel.tsx`) |
| **KEEPERHUB → simulation/receipt** | `packages/keeperhub/src/client.ts` | Trusted-but-independently-reconciled — Gate 6 never marks `FULFILLED_VERIFIED` from KeeperHub's own "completed" status alone (proven, `receipt.test.ts`) | Response shape validated before use | KeeperHub may fulfill governance authority, never reinterpret it (frozen invariant) | Typed errors; not reachable from the live web app at all (F-06) | Configured client-side in the KeeperHub client (proof-script context only) | Not audited further — offline-script-only surface, explicitly out of this gate's live-app focus | API key only ever read by proof scripts (grep-confirmed absent from `apps/web/src`) | Never read by the deployed app |
| **DATABASE → persisted jobs/events/claims** | `packages/db` | Trusted (this app's own write) but not infallible — see F-01/F-07 | JSON round-trip via JSONB (Postgres) / TEXT (SQLite); typed `PersistenceError` taxonomy (extended this gate, F-07) | None — the DB stores decisions already made, never makes them | Fails closed with typed errors, never silently substitutes a different backend (`PersistenceConfigurationError`) | 10-15s `connect_timeout` (Postgres) | None at the store layer | Connection string never logged (`onnotice` suppresses driver NOTICE spam without ever logging params) | `DATABASE_URL` never appears in any log/error message (verified by test, F-07) |
| **ENVIRONMENT → secrets/config** | `process.env` | Trusted but many variables have no format validation — see `env-audit.md` | Ad hoc per-variable (some strict, `MARKED_STORAGE_DRIVER`/`MARKED_ALLOW_DESTRUCTIVE_DB_TESTS`; some loose, `DATABASE_URL`/RPC URLs) | N/A | Mixed — some fail closed cleanly (F-07/F-08 fixed two gaps this gate), some fail late with a generic upstream error | N/A | N/A | Values never logged (grep-confirmed no `console.log(process.env...)` pattern anywhere) | See `secrets-audit.md` for the full scan |
| **BROWSER → form values/cookies/Server Actions** | Every `"use client"` component | Untrusted | React's own escaping (no `dangerouslySetInnerHTML` found anywhere in `apps/web/src`); Server Actions get Next's built-in Origin-check CSRF protection (Route Handlers do not — see `auth-audit.md`) | None | Zod/manual validation per entry point; malformed input rejected, not silently coerced | N/A | N/A | N/A | No secret-bearing prop found passed from a Server Component into a Client Component (traced) |
